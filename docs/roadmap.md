# Implementation roadmap

Each phase ends with: features implemented, files and modules, migrations, tests run with actual results, integrations verified, remaining limitations, and run instructions. The [feature matrix](feature-matrix.md) is updated at the same time.

| Phase | Scope | Exit criteria |
|---|---|---|
| **1. Foundation** (done) | Monorepo, auth with MFA, RBAC, tenant isolation, audit log, API framework, app shell | 101 automated tests passing (11 shared, 82 API, 8 web); honest navigation |
| **2. Physical DCIM** (done) | Datacenter → building → room → row → rack hierarchy; device models; devices with lifecycle state machine; rack elevation (front and rear) with drag-and-drop placement validated by a database exclusion constraint; movement history; spare parts; CSV import/export; QR labels; attachments (S3) | Done: 162 automated tests passing (12 shared, 142 API, 8 web), independent review findings fixed |
| **3. Network and IPAM** | Network devices, interfaces (physical and logical, LAG membership), cables, LLDP/CDP discovery (SNMP), topology from verified sources only, VLANs, VRFs, circuits, IPv4/IPv6 prefixes and addresses with atomic allocation, credential vault, adapters: SNMP, RouterOS REST, FortiOS REST, NX-API (read-only) | Concurrent-allocation and conflict tests; adapter simulator tests |
| **4. Real-time network monitoring** | Worker and scheduler processes, BullMQ polling, IF-MIB HC counters, rate engine (wrap, reset, gaps, speed change, LAG de-duplication), TimescaleDB hypertables and aggregates, SSE live updates, per-port table and detail charts, alert rules with duration and consecutive-sample logic, maintenance suppression, notifications | Rate-engine unit tests for every edge case listed in the brief; poller keeps running with no clients connected |
| **5. Equipment power** | Redfish/iDRAC and IPMI DCMI power collection, SNMP PSU/PDU where exposed, power profiles and estimates, source priority without double counting, time-weighted energy integration, tariffs, rack, datacenter and category totals with measured, estimated and unknown kept separate | Calculation tests (integration, gaps, duplicates, unknowns); no physical meters required |
| **6. Provisioning and virtualization** | Idempotent job state machine (Queued → … → Completed, plus Failed, Cancelled, Recovery), PXE/iPXE and Redfish virtual-media install paths, OS image library with checksums, Proxmox and Virtualizor adapters | Retry and recovery tests; success only after verification |
| **7. Colocation and customer portal** | Allocations (full, half, quarter, custom), contracted power, cross-connects, receiving, visitors, remote hands and tickets, customer self-service views including power and bandwidth | Tenant-isolation tests on every new resource |
| **8. Billing and automation** | WHMCS module and signed idempotent webhooks, service lifecycle sync, workflows (triggers, conditions, approvals, dry-run), reports (CSV/PDF, scheduled email), API keys, webhook subscriptions | Duplicate-webhook tests; reconciliation |
| **9. Production readiness** | Installer validated on a clean Ubuntu LTS VM, backup and restore drills, security review, load test of the poller, admin and customer guides, acceptance report | Recorded install, restore and acceptance runs |

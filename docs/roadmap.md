# Implementation roadmap

Each phase ends with: features implemented, files and modules, migrations, tests run with actual results, integrations verified, remaining limitations, and run instructions. The [feature matrix](feature-matrix.md) is updated at the same time.

| Phase | Scope | Exit criteria |
|---|---|---|
| **1. Foundation** (done) | Monorepo, auth with MFA, RBAC, tenant isolation, audit log, API framework, app shell | 101 automated tests passing (11 shared, 82 API, 8 web); honest navigation |
| **2. Physical DCIM** (done) | Datacenter → building → room → row → rack hierarchy; device models; devices with lifecycle state machine; rack elevation (front and rear) with drag-and-drop placement validated by a database exclusion constraint; movement history; spare parts; CSV import/export; QR labels; attachments (S3) | Done: 162 automated tests passing (12 shared, 142 API, 8 web), independent review findings fixed |
| **3. Network and IPAM** (done) | Network devices, interfaces (physical and logical, LAG membership), cables, LLDP/CDP discovery, topology from verified sources only, VLANs, VRFs, circuits, IPv4/IPv6 prefixes and addresses with atomic allocation, credential vault, discovery worker, adapters: SNMP, RouterOS REST, FortiOS REST, NX-API (read-only) | Done: 261 automated tests passing (21 shared, 230 API, 10 web), including concurrent-allocation, adapter simulator, scheduling and DNS publishing tests; findings from two independent reviews fixed |
| **4. Real-time network monitoring** (done) | Interface polling in the worker (claimed from PostgreSQL rather than BullMQ), IF-MIB HC counters and vendor API counters, rate engine (wrap, reset, gaps, speed change, LAG de-duplication), raw + 5-minute + hourly storage in plain PostgreSQL (TimescaleDB deferred), SSE live updates, per-port table and charts with 95th percentile, alert rules with duration and consecutive-sample logic, maintenance suppression, notifications (email, webhook, Slack, Telegram) | Done: 301 automated tests passing (21 shared, 270 API, 10 web), with a rate-engine unit test for each edge case and a poller that runs in the worker with no client connected; independent review findings fixed |
| **5. Equipment power** (done) | Redfish and IPMI DCMI power collection, APC metered PDU outlets over SNMP, RouterOS and NX-OS supply power, PDU outlet mapping, per-device estimates and model typical draw, source priority without double counting, time-weighted energy (hourly, measured / estimated / unknown kept apart), tariffs, rack, datacenter, category and customer totals, CSV export | Done: 340 automated tests passing (21 shared, 309 API, 10 web), including calculation tests for integration, gaps, duplicates, priorities, estimates and unknowns (17 unit tests) and end-to-end tests against simulated BMCs and PDUs; no physical meters used; independent review findings fixed |
| **6. Provisioning and virtualization** (done) | Idempotent job state machine (Queued → … → Completed, plus Failed, Cancelled, Recovery), PXE/iPXE and Redfish virtual-media install paths, OS image library with checksums, power actions behind `hardware.control` with typed confirmation, Proxmox and Virtualizor adapters | Done: 387 automated tests passing (21 shared, 356 API, 10 web), including retry, crash-recovery, cancellation, deadline, idempotency and verification tests against simulated BMCs, an image mirror and hypervisor APIs; a job completes only after its result is checked, and is labelled "not verified" where the equipment can't show it; independent review findings fixed |
| **7. Colocation and customer portal** (done) | Allocations (full, half, quarter, custom), contracted power, cross-connects, receiving, visitors, remote hands and tickets, orders & services, customer self-service views including power and bandwidth | Done: 407 automated tests passing (21 shared, 376 API, 10 web), with tenant-isolation checks on every new resource; independent review findings fixed |
| **8. Billing and automation** | WHMCS module and signed idempotent webhooks, service lifecycle sync, workflows (triggers, conditions, approvals, dry-run), reports (CSV/PDF, scheduled email), API keys, webhook subscriptions | Duplicate-webhook tests; reconciliation |
| **9. Production readiness** | Installer validated on a clean Ubuntu LTS VM, backup and restore drills, security review, load test of the poller, admin and customer guides, acceptance report | Recorded install, restore and acceptance runs |
